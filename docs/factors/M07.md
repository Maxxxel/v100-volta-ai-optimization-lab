## Theory and Volta implications

Chat templates and instructions determine how native roles and tool syntax reach the model. Correct model-specific formatting precedes speed comparison.

On SM70, require an actually dispatched compatible kernel and include conversion, workspace, launch and verification costs. The 16 GB budget includes weights, attention KV, recurrent states, graph pools and transient allocations. Quality, end-to-end latency and energy per successful task take precedence over a token-throughput screen.

## Decision and remaining research

Original native template and successful tool scopes retained; description/schema shortening and exact policy-position R302 have separate quality vetoes.

**Remaining scope:** A genuinely new template requires a documented semantic/role/tool contract and fixed candidate bytes before unseen-quality evaluation. A later system role is forbidden by this original template, not a valid blind variant.

**Reopening condition:** A genuinely new template requires a documented semantic/role/tool contract and fixed candidate bytes before unseen-quality evaluation. A later system role is forbidden by this original template, not a valid blind variant.

**Next action:** Keep original template. No same-description/policy permutation retries tuned on known answers.

These canonical rationale excerpts preserve the original language. Potential combinations require independently qualified constituents and fresh interaction controls. Transfer to another model requires compatible architecture, weights, tokenizer, state layout and engine dispatch.
