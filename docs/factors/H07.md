## Theory and Volta implications

Swap and hugepages affect host memory behavior. Global host changes require an isolated capacity hypothesis and do not prove GPU progress.

On SM70, require an actually dispatched compatible kernel and include conversion, workspace, launch and verification costs. The 16 GB budget includes weights, attention KV, recurrent states, graph pools and transient allocations. Quality, end-to-end latency and energy per successful task take precedence over a token-throughput screen.

## Decision and remaining research

Host swap is already occupied; its prior causal origin was not established. This is not evidence of new model swapping. R373 model VmSwap is0kB and adds0swap. Explicit hugepage pool currently0, THP=madvise. Hostwide swap/hugetlb changes would affect protected Proxmox/services; THP advice and explicit hugetlb are different mechanisms.

**Remaining scope:** Useful workload with measured model paging/translation cost and a private bounded memory policy; explicit hugetlb needs a separately available nonproductive pool. Do not induce global memory pressure or disable host swap.

**Reopening condition:** Useful workload with measured model paging/translation cost and a private bounded memory policy; explicit hugetlb needs a separately available nonproductive pool. Do not induce global memory pressure or disable host swap.

**Next action:** Useful workload with measured model paging/translation cost and a private bounded memory policy; explicit hugetlb needs a separately available nonproductive pool. Do not induce global memory pressure or disable host swap.
