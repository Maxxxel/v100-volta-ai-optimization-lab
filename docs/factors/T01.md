## Theory and Volta implications

LoRA/QLoRA train adapters with reduced optimizer state. The exact hybrid/MTP implementation and a real training step must fit the device.

On SM70, require an actually dispatched compatible kernel and include conversion, workspace, launch and verification costs. The 16 GB budget includes weights, attention KV, recurrent states, graph pools and transient allocations. Quality, end-to-end latency and energy per successful task take precedence over a token-throughput screen.

## Decision and remaining research

R378 full-model trainer limitation remains. New CPU-only proof uses the already pinned native ggml_opt API for a reduced frozen-feature rank-8 output-LoRA graph at actual 4096x248320 tensor dimensions; one AdamW update and one independent analytic-gradient probe pass. This establishes CPU graph/API feasibility only; actual adapter file registration, SM70 execution, device memory, model-derived feature capture and training quality remain unverified.

**Remaining scope:** Verify adapter metadata/registration and independent train/dev split; capture result_norm from the pinned Omni model, then run one bounded GPU optimizer step and measure actual VRAM/dispatch. No task quality or training benefit from the synthetic CPU oracle.

**Reopening condition:** Demonstrate actual trainableadapter registration, compatibleQwen35GDN/autograd or a correctly frozen-backbone path, private data split and one boundedFP16/SM70optimizerstep with measuredmemory. No blanketclaimthatQLoRAcannotfit16GB.

**Next action:** Freeze actual adapter tensor registration/metadata and train/dev data; verify 16-bit/F32 choices and V100 CUDA dispatch/resource behavior, then capture only result_norm on disjoint R187-derived training tokens and perform one bounded GPU step under existing broker guards.

These canonical rationale excerpts preserve the original language. Potential combinations require independently qualified constituents and fresh interaction controls. Transfer to another model requires compatible architecture, weights, tokenizer, state layout and engine dispatch.
